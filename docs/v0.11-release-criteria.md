# v0.11 release criteria — what "done" means

The Game Test Lab's red flag was that v0.11 had no stated pass criteria or
release path: no defined success rate, time, or checklist that would mark
it done. This page is that definition. Nothing here is claimed as passed
until a proof log in `proof-runs/` says so.

## Status (2026-11-20)

**Not passed.** Argon was not running on the HP laptop, port 8080 did not
respond, and the Zombie shootout proof app had not been built, run, or
playtested. The core loop is unproven on its target platform and hardware.
The work in this update (startup doctor, health endpoint, proof-run script,
snapshot test, scope freeze) exists to make the loop runnable and
measurable — it is not itself a pass.

## The gate: the Windows 7–8B loop, twice in a row

v0.11 is done when the same loop passes **twice in a row** on the HP laptop
with a real Ollama 7–8B model (`qwen2.5-coder:7b`):

```
prompt -> plan -> build -> run -> playtest report
```

Each pass is one proof log in `proof-runs/` (produced by `npm run proof`)
with every automated check `pass` and the manual playtest filled in.
Two consecutive passing logs — no failing run in between — is the release.

## Per-run pass criteria

A single proof run passes when all of these hold:

| Check | Pass means |
| --- | --- |
| health | Argon responds on its port; Ollama reachable; the 7–8B model is pulled |
| plan | Argon returns a usable plan for the proof app (not an error, not empty) |
| build | A complete, valid game file is proposed and applied through the approve path |
| run | The built file reads back through Argon and is a complete HTML document |
| playtest | A person opened the game in a browser, played it, and recorded the result in the log (loads, shooting/tapping scores, timer ends, game-over screen shows) |
| fix attempts | 3 or fewer fix attempts were needed for the build (recorded in the log) |
| snapshot restore | `npm run snapshot-test` passes: break a file, restore from the safety snapshot, contents verified |

## Numbers every log must record

- Time taken per step (plan, build, run) in milliseconds.
- RAM: Argon process RSS and system free memory, before and after the run.
- Token counts from Ollama per chat call (prompt / response), as reported
  by `/api/chat` in the `usage` field.
- Fix attempts used (0–3).
- Build success rate and fix-it success rate across runs (counted from the
  logs, not estimated).

These numbers are the evidence. Chat screenshots are not evidence; a
hand-edited log is not evidence — logs are written by `npm run proof` and
committed as written.

## Release checklist

- [ ] `npm run doctor` passes on the HP laptop.
- [ ] Two consecutive proof logs pass (see the gate above).
- [ ] `npm run snapshot-test` passes.
- [ ] The Zombie shootout (or the smaller fallback, if it stalls and the
      stall is recorded) plays end to end in a browser.
- [ ] No scope-freeze item was built during the runs (`SCOPE-FREEZE.md`).
- [ ] README startup steps match what actually worked on the laptop; any
      step that did not work is corrected in `STARTUP.md` with the real error.

## What is out of scope for v0.11

Phone fallback, the 14B trial, agent roles, and multi-step autonomy — see
`SCOPE-FREEZE.md`. They stay parked until the gate passes.
